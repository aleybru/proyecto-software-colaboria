Corregir el modelo de recursos de proyecto: la UI dejaba elegir `kind` y `provider` de forma independiente, permitiendo combinaciones sin sentido (ej. `governance_repo` + Google Drive). Fijar que cada `kind` tiene un `provider` fijo, y cada tipo de proyecto espera un conjunto fijo de slots de recursos, no una lista abierta.

## Qué se hizo (reconstruido de la evidencia real)

- Backend: nuevo `ResourceCatalog` como fuente de verdad `kind → provider` y `tipo de proyecto → kinds esperados`, validado server-side.
- `link`/`provision` de recursos dejan de recibir `provider` en el body y hacen upsert por `kind`.
- Nuevos endpoints `PATCH`/`DELETE` de proyecto y `PUT`/`DELETE` de recurso (cambiar vínculo / desvincular) — no tocan GitHub/Drive reales, solo el registro en la DB.
- `GET` de detalle de proyecto devuelve slots + `overallStatus`.
- Sin migración nueva de EF Core (confirmado con `dotnet ef migrations has-pending-model-changes`, según el mensaje de commit original).
