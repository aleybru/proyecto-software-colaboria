## Objetivo

**Nota de trazabilidad:** reconstrucción retrospectiva, escrita el 2026-08-30. Identificada en los commits del repo de código como **"TASK-0011"** — se conserva ese ID histórico como alias; el ID canónico en `code-tasks/` es **TASK-0012**.

Cuando el refresh token de Google Drive dejaba de ser válido, el aprovisionamiento fallaba con un error genérico ("provisioning_error") que le pedía al usuario llamar a mano a un endpoint interno (`GET /integrations/google-drive/authorize`). Implementar un flujo integrado de reautorización, sin exponer detalles de endpoints al usuario.

## Qué se hizo (reconstruido de la evidencia real)

- Clasificación explícita del caso de refresh token inválido (`invalid_grant` real, confirmado contra la cuenta en uso) en `GoogleDriveService.ClassifyTokenRefreshError`, como estado tipado `reauthorization_required` — separado de un error transitorio de red o un error real de la API de Google.
- `OAuthStateStore` extendido para cargar `projectId`/`resourceId` opcionales en el "state" de OAuth — único canal por el que ese contexto puede viajar a través del round-trip a Google.
- `GET /authorize` valida ese estado antes de redirigir.
