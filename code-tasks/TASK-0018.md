## Objetivo

Implementar el núcleo persistente del canal conversacional (Bloque D de DEC-C16, primer corte): modelo de datos y contrato mínimo para `sessions`, `messages` y `agent_turns`, con aislamiento estricto por proyecto e idempotencia. **Sin routing, sin `both_sequential`, sin adapters de proveedor, sin llamadas reales a OpenAI/Anthropic, sin frontend de sala, sin Context Builder real, sin approvals/gateway.**

## Contexto de diseño (resultado del contraste Papu/Chapu, no repetir la discusión — partir de acá)

Contraste completo en `handoffs/quick/log.md`, entradas del 2026-08-30. Resoluciones ya cerradas:

- `input_context_ref` queda **nullable** en esta tarea — DEC-C10 punto 6 exige que sea "trazable y verificable, no texto decorativo"; sin Context Builder real, forzarlo `NOT NULL` obligaría a guardar un placeholder. Se vuelve obligatorio cuando exista Context Builder (tarea futura), no acá.
- Los agentes (`papu`/`chapu`) **no son una tabla de Postgres** — son configuración en memoria (`AgentRegistry`, TASK-0016). La validación de `agent_id` en `messages`/`agent_turns` es de **aplicación**, no una FK real de Postgres.
- **Conversar no pasa por `AgentAuthorizationService`** (TASK-0017). Esa política regula el techo de efectos sobre `project_state`/Drive/repo de código — conversación no es estado ni efecto secundario por sí misma (protocolo común, sección 8: "conversación no es estado").
- Completar un turno exitoso debe ser **una única transacción de DB**, no una secuencia de escrituras separadas.

## Qué tiene que hacer Code (concreto)

### 1. Modelo de datos (EF Core + Postgres)

**`sessions`:**
- `id`
- `project_id` (obligatorio — DEC-C10 punto 1; FK real a `projects`, TASK-0007)
- `created_at`, `updated_at`

**`messages`** (fuente de verdad del contenido — DEC-C10 punto 2):
- `id`
- `session_id` (FK real a `sessions`)
- `role`: `user` | `agent` (V0 — sin otros roles todavía)
- `agent_id`: string, **requerido solo cuando `role = agent`**, validado en aplicación contra `AgentRegistry` (sin FK real — ver contexto de diseño)
- `content`
- `client_message_id`: requerido cuando `role = user`, **único por sesión** (idempotencia — DEC-C10 punto 3)
- `created_at`

**`agent_turns`** (bitácora de cómo se generó una respuesta — DEC-C10 punto 2):
- `id`
- `session_id` (FK real)
- `agent_id` (string, validado en aplicación)
- `agent_definition_hash` (de TASK-0016 — ancla el turno a la versión exacta del perfil usado)
- `provider`, `model` (snapshot del `RuntimeBinding` usado, no una referencia mutable)
- `status`: `running` | `succeeded` | `failed` | `timeout`
- `started_at`, `finished_at` (nullable hasta terminar)
- `timeout_at` (explícito — DEC-C10 punto 4, ningún turno queda indefinidamente en `running`)
- `input_context_ref` (**nullable** — ver contexto de diseño)
- `error` (nullable)
- `output_message_id` (FK nullable a `messages` — solo se completa si `status = succeeded`)

### 2. Atomicidad (requisito explícito, no implícito)

Completar un turno exitoso (`agent_turn.status = succeeded` + creación del `message` del agente + `agent_turn.output_message_id` apuntando a ese mensaje) tiene que ejecutarse dentro de **una única transacción de base de datos**. Un fallo a mitad de camino no puede dejar un `agent_turn` en `succeeded` sin `message`, ni un `message` de agente sin `agent_turn` que lo respalde.

### 3. API mínima (para verificar el slice, no como superficie pública final)

- Crear sesión dentro de un proyecto.
- Persistir un mensaje de Dani, idempotente por `client_message_id` dentro de la sesión (reintentar con el mismo `client_message_id` no duplica).
- Leer transcript de una sesión (mensajes en orden).

`agent_turns` queda como servicio interno — **sin endpoint HTTP público todavía** en esta tarea (no hay adapters que lo disparen desde afuera).

### 4. Aislamiento estricto por proyecto

Ninguna consulta de sesión, mensaje o turno puede cruzar el límite de proyecto — el proyecto B no puede leer sesiones, mensajes ni transcript del proyecto A, ni por error de query ni por parámetro manipulado.

## Criterio de éxito

- Migración de EF Core real aplicada contra Postgres, con las FKs/constraints descriptas (incluida la unicidad de `client_message_id` por sesión).
- Reiniciar el backend conserva sesiones/mensajes/turnos ya persistidos (no es estado en memoria).
- Reintentar el mismo `client_message_id` dos veces en la misma sesión no duplica el mensaje.
- Un proyecto B, mediante cualquier combinación de IDs, no puede leer sesión, mensajes ni transcript de un proyecto A — verificado con un test que lo intente explícitamente.
- Test de atomicidad: forzar una excepción entre la creación del `message` del agente y la actualización de `agent_turn.output_message_id` (o el paso equivalente), y confirmar que **no** queda ni un `message` huérfano ni un `agent_turn.status = succeeded` sin `message` vinculado.
- Un `agent_turn` en `running` que supera su `timeout_at` no queda indefinidamente así — pasa a `timeout` de forma verificable (mecanismo exacto a criterio de Code, documentado en `## Resultado`).
- `dotnet build` sin errores; `dotnet test` sin regresiones sobre la suite existente (TASK-0001 a TASK-0017).

## Contexto / restricciones

- No implementar floor lock, `both_sequential`, adapters de proveedor, llamadas reales a OpenAI/Anthropic, frontend de sala, Context Builder real, approvals ni gateway — todo eso es alcance de tareas posteriores del Bloque D/E.
- No crear un endpoint HTTP público para disparar `agent_turns` — no hay nada todavía que lo consuma de forma real.
- No forzar `input_context_ref` a `NOT NULL` ni completarlo con un valor decorativo — debe quedar nullable, sin excepciones, hasta que exista Context Builder real.
- No intentar una FK de Postgres hacia una tabla de agentes — no existe tal tabla; `agent_id` se valida en aplicación contra `AgentRegistry` (TASK-0016).
- Respetar DEC-C08: detalles técnicos menores (mecanismo exacto de detección de timeout, forma interna de la transacción) quedan a criterio de Code, documentados en `## Resultado`. Si aparece una contradicción real con DEC-C10/DEC-C16 durante la implementación, señalarla explícitamente en vez de resolverla por criterio propio.
